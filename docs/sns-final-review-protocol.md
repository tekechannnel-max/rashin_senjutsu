# SNS最終検査プロトコル

作成日: 2026-05-12

このプロトコルは、羅針占術のThreads/X投稿を公開前に検査するためのものです。目的は、単なる誤字チェックではなく、心理・SNS運用・事業導線・企画状況・倫理の全方向から、投稿してよい内容かを判定することです。

## 0. 最初に固定する前提

投稿文を見る前に、必ず次を確定します。

- 今日の日付とJST時刻
- フェーズ: `prelaunch` / `launch` / `postrelease`
- 今日ユーザーが実際に取れる行動
- 投稿先: Threads / X
- 投稿種別: 朝オラクル / 夜コンセプト / 告知 / 導線説明
- 画像の有無とalt text
- アプリ、無料鑑定、BOOTH、注文番号確認の本番状態
- すでに同日同種の投稿が出ていないか

ここを間違えると、文章だけ直しても失敗します。特にプレリリース前は「まだ使えないもの」を「今すぐ使える」ように見せないことを最優先します。

## 1. ハードストップ

以下に1つでも該当したら投稿しません。修正して再検査します。

- プレリリース前に公開URL、UTM、購入リンクを表示している
- プレリリース前に「あなたも今日の1枚を引かない？」など、今すぐ利用できるCTAを使っている
- 実際には未確認の機能を「使えます」「始められます」と断定している
- 未来、相手の気持ち、健康、投資、法律判断を断定している
- 不安を煽って購入、課金、深掘り鑑定へ誘導している
- BOOTH確認フローが本番確認前なのに、価格・購入・注文番号入力を強く出している
- Threadsで500文字を超えている
- ハッシュタグが複数ある、または `#羅針占術` がない
- ThreadsとXで完全同文を使っている
- 同じ日付・同じ導線・同じ文面を重複投稿しようとしている

## 2. 6つの検査レンズ

### A. 状況整合性

- この投稿は今日のフェーズに合っているか
- ユーザーが今できる行動だけを促しているか
- プレリリース前なら「5/16公開予定」「先行版」「フォロー/保存/待つ」に寄っているか
- 公開後なら「今日のオラクル」「無料鑑定」「必要なら深掘り」の順番になっているか

### B. 読者心理

- 読者の不安を強くしすぎていないか
- 読者が保存・フォロー・見返しをしたくなる理由があるか
- 「自分のことかも」と思える具体性があるか
- 読後に小さな行動が残るか
- 依存ではなく自己理解に向かっているか

### C. SNS運用

- 冒頭1〜2行で何の投稿か分かるか
- 1投稿1テーマになっているか
- 改行が読みやすく、スマホで詰まりすぎないか
- Threadsでは会話・保存・フォローのどれを狙うか明確か
- Xを使う場合は短く、検索語が入り、Threadsの単純転載になっていないか

### D. 事業導線

- SNS上では無料行動を主導線にしているか
- 有料は「必要な方だけ」「深く整理したい方向け」に留めているか
- 無料オラクル、無料鑑定、深掘り鑑定の役割が混ざっていないか
- 価格や購入を出す場合、本番フロー確認後か
- 投稿単体の価値があり、売り込みだけになっていないか

### E. 倫理・信頼

- 「絶対当たる」「運命の人」「必ず戻る」などを使っていないか
- 医療、法律、投資、健康の専門判断の代替に見えないか
- 相手の気持ちを断定していないか
- 悪い未来を匂わせて課金へ誘導していないか
- 公式感、落ち着き、責任ある距離感があるか

### F. ブランド

- 羅針占術らしい「迷いを次の一手に変える」軸があるか
- 怖い占い、煽る占い、恋愛不安商材に見えていないか
- 「本質・本音・いまの現実・次の一手」のどれかに接続しているか
- 毎日見ても疲れないトーンか

## 3. フェーズ別CTA

### プレリリース前

使うCTA:

- 気になる方はフォローして、5/16の公開を待っていてください。
- 気になった方は保存して、5/16に見返してください。
- 明日の公開を見逃さないよう、フォローして待っていてください。

避けるCTA:

- あなたも今日の1枚を引かない？
- 今すぐ無料鑑定へ
- アプリで試してみてください
- BOOTHで購入してください

### プレリリース開始日

使うCTA:

- まずは無料の「今日のオラクル」からどうぞ。
- もう少し整理したい方は、無料鑑定へ。
- 必要な方だけ、無料鑑定のあとに深掘り鑑定へ進めます。

### 公開後

使うCTA:

- あなたも今日の1枚を引かない？
- 今日のオラクルで、今の流れを見てみてください。
- 無料鑑定で、本質・本音・いまの現実・次の一手を整理できます。

有料CTAは、BOOTH購入と注文番号確認が本番で確認できた後だけ強めます。

## 4. 投稿前の判定

各投稿を次の4段階で判定します。

- `BLOCK`: 投稿禁止。事実、倫理、フェーズ、導線のどれかが崩れている
- `REWRITE`: 投稿可能性はあるが、訴求・構成・CTAが弱い
- `PASS`: 投稿可。最低限の品質と安全性を満たす
- `STRONG`: 投稿可。保存・フォロー・導線の理由が明確

`PASS`未満は投稿しません。プレリリース前は、以下を満たさない投稿は原則 `REWRITE` 以下です。

- 5/16公開前であることが分かる
- まだ使えないものを使えるように見せていない
- フォローまたは保存する理由がある
- 有料導線が強すぎない
- 羅針占術の思想が伝わる

## 5. Codexレビューの出力形式

投稿前レビューでは、最低限この形で出します。

```text
判定: PASS / REWRITE / BLOCK / STRONG
フェーズ: prelaunch / launch / postrelease
対象: Threads 朝オラクル / Threads 夜コンセプト / X

確認:
- 今日ユーザーが取れる行動:
- CTAの妥当性:
- 心理的な引き:
- 事業導線:
- 倫理リスク:
- 文字数/ハッシュタグ:

修正が必要な場合:
- 問題:
- 修正文:
```

## 6. 投稿後の検査

投稿後も完了扱いにする前に確認します。

- Threads APIの投稿IDだけでなく、permalinkまたは取得結果で本文を確認したか
- 画像付き投稿なら画像またはフォールバック結果を確認したか
- 同日重複投稿になっていないか
- 誤投稿があった場合、API削除可否と手動削除手順を切り分けたか
- 誤投稿の原因をスクリプトまたはチェックリストに戻したか

誤投稿の対応は「URLだけ消せばよい」ではありません。フェーズ、CTA、利用可能性、読者心理、導線まで見直します。
