# カードリーディング意味準拠ルール

対象: `app.js` の無料・有料カードリーディング、`scripts/social/*` のSNS画像・投稿文。

## 共通原則

- カード本文は、カードの辞書的説明ではなく、相談者の現実・違和感・運気・流れ・支え・転機へ翻訳する。
- カード名、枚数、配置語、占術説明は、根拠表示以外の本文に出さない。
- 読者へ作業を強いる言い方を避ける。禁止寄りの語: `確認する`、`書き出す`、`整理する`、`比較する`、`材料を集める`、`距離を測る`、`チェックする`。
- 弱い読み: カードの辞書的意味だけ、業務メモ、作業手順、読者への宿題になっている。
- 強い読み: カード固有の意味があり、今日の運気・予兆・心理的な流れ・現実の見立てとして読める。
- 占い読みとして自然な語感: `兆し`、`予兆`、`気配`、`運気`、`流れ`、`サイン`、`暗示`、`前触れ`、`予感`、`導き`、`光`、`風`、`影`、`扉`、`鍵`、`巡り`、`転機`、`山場`、`羅針`、`指針`、`引力`。

## NG/OK

- NG: `情報を読む`、`書類を確認する`、`距離を測る`、`流れを見る`、`条件を整理する`。
- OK: `返事が流れを変える`、`隠れた本音が影に潜む`、`希望の光が戻る`、`迷いは転機の印`。
- NG: `連絡や書類が動く` のような単なる現実描写で止める。
- OK: 手紙なら `知らせが運気を動かす`、`返事が流れを変える` のように、カードの意味から出る予兆へ変換する。

## アプリ本体への適用

- `app.js` のAI鑑定プロンプトでは、カード意味を `今日の運気 / 兆し / 現実の流れ / 違和感 / 支え / 転機 / 羅針の指針` として読むことを必須にする。
- `detectTaskLikeReadingIssues` で、作業指示・業務メモ化した鑑定本文を品質問題として検出する。
- 無料鑑定の `applyFreeReadingQualityGate` と有料鑑定の `validatePaidReadingQuality` の両方で、この検査を通す。
- リーディング本文は現実語へ翻訳してよいが、確認作業・条件整理・ToDoリストで終わらせない。

## 検証項目

- `npm run check` を通す。
- `app.js` の `detectTaskLikeReadingIssues` が無料・有料の品質ゲートに入っていることを確認する。
- SNS画像は生成後に実画像を開き、背景、文字、カード意味、重なり、可読性を確認する。
