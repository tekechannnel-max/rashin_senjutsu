# SNS投稿 絶対ルール

作成日: 2026-06-05
最終改定日: 2026-06-15
対象: 羅針占術のThreads / Instagram投稿、投稿文生成、画像生成、予約投稿、自動投稿設定、削除、再投稿

このファイルは、SNS投稿作業で最初に読む強制ルールです。`docs/sns-runbook.md` やスクリプトが存在していても、このファイルに反する解釈、補完、投稿、削除、再投稿をしてはいけません。

## 最重要原則

AIはユーザーの最新指示を勝手に解釈しない。

素材フォルダ、投稿文、投稿日時、投稿枚数、媒体のどれかが未確定なら、作業を止めて質問する。推測で補完して投稿しない。

## 正本の優先順位

1. ユーザーの最新指示
2. ユーザーが明示的に確定した本文、画像、日時、媒体
3. このファイル
4. `docs/sns-runbook.md`
5. 誕生日数SNSでは `docs/sns-birthday-number-content-guide.md`
6. 現在のスクリプトのdry-run結果

古いJSON、古いdocs、古いチャット要約、過去の投稿事故時の暫定ルールで上位の情報を上書きしてはいけない。

## 作業フローの絶対順序

SNS投稿、投稿文生成、画像生成、動画生成、予約投稿、自動投稿設定、削除、再投稿、復旧対応では、必ず次の順序で進める。

1. `git status --short` と `git diff` で作業前状態を確認する。
2. このファイルを読む。
3. `docs/sns-runbook.md` を読む。
4. 誕生日数、ランキング、あるある、ミニキャラ、Reels動画を扱う場合は `docs/sns-birthday-number-content-guide.md` を読む。
5. ユーザーの最新指示から、日時、媒体、素材、順番、本文、ハッシュタグ、公開URL、外部操作の有無を抜き出す。
6. どれか1つでも未確定なら、作業を止めて質問する。
7. 生成や編集を行う場合は、生成前に正本素材、出力先、上書き有無を確認する。
8. 投稿、削除、再投稿、予約変更、自動投稿設定変更の前に、投稿前承認ゲートを提示する。
9. 外部操作後は、投稿URL、台帳、ログ、重複有無、失敗時の検知方法を確認する。
10. 作業後に `git status --short` と `git diff` を確認し、変更範囲、検証結果、未確認点を報告する。

この順序を飛ばして「たぶん正しい」「前もこうだった」「スクリプト上は動く」で進めてはいけない。

## 現在の投稿ルール

### 毎日 8:00

朝の投稿は、次のフォルダだけを使う。他は絶対に触らない。

```text
D:\株式会社 天仙\羅針占術\images\social\instagram\oracle
```

朝の投稿はThreads / Instagramの両方に投稿する。クラウド側のGitHub ActionsまたはRender Cronで、08:00 JSTのdue確認と投稿前検証が通っていない状態を完了扱いしない。

### 毎日 20:00 / 21:00 / 22:00 / 23:00

夜の通常投稿は、画像・カルーセルではなく動画を標準にする。InstagramはReels、Threadsは動画投稿として扱う。静止画像・カルーセルは、ユーザーが明示した場合だけ例外として扱う。

夜の通常投稿動画は、次のフォルダだけを使う。他は絶対に触らない。

```text
D:\株式会社 天仙\羅針占術\videos\social\instagram\【インスタ】あるある・ランキング系
```

投稿する動画、順番、本文、公開URL、投稿時刻が確定していない場合は投稿しない。

この夜の通常投稿はThreads / Instagramの両方に投稿する。本文は同一趣旨とし、ThreadsとInstagramで変えるのはハッシュタグだけにする。

ReelsはInstagram上の名称なので、Threadsでは同じ動画をThreads動画投稿として扱う。Threads投稿のハッシュタグは1個だけにする。

夜の通常投稿で「Instagramだけ」「Threadsだけ」に片寄せする場合は、ユーザーが明示した場合だけ例外として扱う。

### 木曜日 20:00

木曜日の20:00枠は、夜の通常投稿より優先して、次の3枚だけでカルーセル投稿する。他は絶対に触らない。

```text
D:\株式会社 天仙\羅針占術\images\social\instagram\difference.jpg
D:\株式会社 天仙\羅針占術\images\social\instagram\free-paid-compare.jpg
D:\株式会社 天仙\羅針占術\images\social\instagram\rashin_point.jpg
```

### 毎月1日 20:00 / 21:00 / 22:00 / 23:00

毎月1日は絶対優先で、次のフォルダだけを使う。他は絶対に触らない。

```text
D:\株式会社 天仙\羅針占術\images\social\instagram\誕生日数×ルノルマン
```

このフォルダ配下のサブフォルダと画像は使用してよい。`2026-06\25-31` のような月別・範囲別フォルダも、この指定フォルダ内なので使用可能とする。

毎月1日の20:00 / 21:00 / 22:00 / 23:00には、夜の通常投稿と木曜日20:00投稿を入れない。

毎月1日の誕生日数×ルノルマン月次カルーセルはThreads / Instagramの両方に投稿する。本文は同一趣旨とし、ThreadsとInstagramで変えるのはハッシュタグだけにする。

### 誕生日系のハッシュタグ

誕生日系Instagram投稿には、確定済みの方針として次を必ず入れる。

```text
#誕生日占い
#数秘
```

誕生日系Threads投稿のハッシュタグは、Threads用の確定ハッシュタグ1個だけにする。

### 誕生日数・ミニキャラ・ランキング動画

誕生日数SNSの本文、動画、画像、ミニキャラ選定は `docs/sns-birthday-number-content-guide.md` を正本にする。

ミニキャラは生まれ日を1桁になるまで足した1〜9系だけを使う。11、22、29などを本文でマスターナンバーとして説明しても、ミニキャラは必ず1桁還元後の系にする。

実装では `scripts/social/birthday-mini-family.js` を正本にし、生成スクリプトごとの独自計算、テーマ・順位・背景色・本文の雰囲気によるキャラ選定を禁止する。

動画内CTAの保存誘導は、確定表現として次を基本にする。

```text
保存していつでも思い出してください。
```

羅針占術への誘導は、保存誘導の後に自然につなげる。誤読される煽り、医学的断定、依存を強める表現は使わない。

### 動画デザイン品質

動画は画像切り替えが少ない場合でも、読めることを最優先にする。

- 文字の上に模様、柄、装飾、ミニキャラを重ねない。
- 背景装飾は本文可読性を下げるなら使わない。
- タイトル、順位、生まれ日、理由、保存CTA、羅針占術誘導を一目で追える階層にする。
- 文字量が多い場合は、行間、余白、ブロック分けを優先し、装飾で埋めない。
- 生成後はスクリーンショット、プレビュー、または動画フレームで可読性を確認する。
- 見た目が確認できていない状態で120点、完成、投稿可能と断言しない。

## 投稿前承認ゲート

外部投稿、削除、再投稿、予約変更、自動投稿設定変更の前に、必ず次をそのまま提示する。

- 投稿日時
- platform
- 投稿種別
- 画像/動画パス
- 画像/動画枚数
- 公開URL
- 投稿本文
- ハッシュタグ
- 既知の制限、未確認点、リスク

ユーザーが明確に承認するまで投稿しない。曖昧な返事を承認扱いしない。

## 絶対停止条件

次のどれかに当たる場合は、作業を止めて質問する。推測、分割、代替画像生成、文面変更で回避しない。

- 投稿文が未確定。
- 画像/動画が未確定。
- フォルダ内のどの素材を使うか未確定。
- 画像/動画の順番が未確定。
- 画像/動画枚数がplatform上限にぶつかる。
- ThreadsとInstagramで同一内容か別文か不明。
- 同じ時刻に複数投稿が衝突する。
- 指定フォルダ外の素材を使いそうな場合。
- 既存画像/動画があるのに新規生成しようとしている。
- 外部投稿済みの削除、再投稿、上書きが必要になりそうな場合。

## 禁止

- 勝手に投稿文を作らない。
- 勝手に投稿文を言い換えない。
- 勝手にハッシュタグを抜かない。
- 勝手に画像/動画を新規生成しない。
- 勝手に指定フォルダ外の素材を使わない。
- 勝手に別日へ移動しない。
- 勝手に分割投稿しない。
- 古いJSONの本文を正本扱いしない。
- local dry-runだけで自動投稿完了と言わない。
- 投稿URL未確認のまま投稿成功と言わない。

## 自動投稿の完了条件

「自動投稿できる」と報告できるのは、次を確認した後だけ。

- PCやCodexが起動していなくても動くクラウド実行経路がある。
- Render CronまたはGitHub Actionsの実行時刻がJST投稿時刻に合っている。
- Threads / Instagramの認証情報がクラウド側に設定されている。
- dry-runで対象投稿が正しい時刻にdueになる。
- 実投稿、または実投稿相当の検証で本文、画像/動画、URL、重複有無を確認できる。
- 失敗時に検知できるログ、通知、または監査手順がある。

どれか未確認なら、未確認と明記する。120点と断言しない。

ローカルPCのWindowsタスクスケジューラ、対話型PowerShell、Codex実行中の一時プロセスは、緊急回復用の暫定手段に限る。これらは画面を閉じる、セッションが切れる、電源状態が変わる、タスクが強制終了するなどで失敗するため、自動投稿できる状態とは報告しない。
