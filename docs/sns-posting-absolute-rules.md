# SNS投稿 絶対ルール

作成日: 2026-06-05
対象: 羅針占術のThreads / Instagram投稿、投稿文生成、画像生成、予約投稿、自動投稿設定、削除、再投稿

このファイルは、SNS投稿作業で最初に読む強制ルールです。`docs/sns-runbook.md` やスクリプトが存在していても、このファイルに反する解釈、補完、投稿、削除、再投稿をしてはいけません。

## 根本原因

今回の失敗の根本原因は、投稿文や画像の細部ではありません。

- 正しい指示の出どころを確定しないまま進めたこと。
- ユーザーの言葉を、古いdocs、古いJSON、古い実装で補完したこと。
- 外部投稿という取り返しにくい操作の前に、本文、画像、枚数、日時、媒体を提示して承認を取らなかったこと。
- 不明点、上限衝突、素材不足があるのに止まらなかったこと。
- 「自動投稿」を、クラウド実行、認証、次回予定、失敗通知まで確認した状態として扱わなかったこと。

## 最重要原則

AIはユーザーの言葉を勝手に解釈しない。

少しでも解釈違いが起き得る場合は、作業を止めて質問する。推測で進めるより、停止するほうを正とする。

## 正本の優先順位

SNS投稿では、次の順で正しい情報を決める。

1. ユーザーの最新指示
2. ユーザーが明示的に「これでいこう」と確定した本文、画像、日時、媒体
3. このファイル
4. `docs/sns-runbook.md`
5. 現在のスクリプトのdry-run結果
6. 過去の生成済みJSON、古いdocs、古いチャット要約

下位の情報で上位の情報を上書きしてはいけない。矛盾がある場合は投稿しない。

## 現在の投稿設定

```text
毎朝8:00:
  朝のオラクル
  対象: Threads / Instagram

毎月1日 20:00 / 21:00 / 22:00:
  誕生日数 x ルノルマン占いのカルーセル投稿
  対象: Instagram
  必須: 1〜31日生まれの占い画像であること

毎月1日以外の毎日20:00:
  誕生日数あるある、またはランキングの画像投稿
  対象: Threads / Instagram
  必須: 画像と投稿文が確定していること

毎週木曜20:00:
  比較系3種のカルーセル投稿
  対象: Threads / Instagram
  Threads: 3枚画像投稿
  注意: 同じ画像を毎週繰り返す意味ではない

絶対ルール:
  毎月1日の月次カルーセル投稿と、毎月1日以外の20:00投稿は、同じ日に投稿しない。
  ②と③は同日投稿されない前提で設計・監査・予約する。
```

## 2026-06-06 月次リカバリ

2026年6月分の誕生日数 x ルノルマン月次カルーセルは、2026-06-05の投稿事故後、2026-06-06にリカバリする。

```text
2026-06-06 20:00:
  1〜10日生まれ
  対象: Instagram

2026-06-06 21:00:
  11〜20日生まれ
  対象: Instagram

2026-06-06 22:00:
  21〜30日生まれ
  対象: Instagram

2026-06-06 23:00:
  31日生まれ
  対象: Instagram
```

`21〜31日生まれ` は11枚でInstagramカルーセル上限10枚に衝突するため、2026-06-06のリカバリでは `21〜30` と `31` を別投稿にする。これはユーザー確認済みの例外であり、他の日付や月に勝手に流用してはいけない。

## 投稿前承認ゲート

外部投稿、削除、再投稿、予約変更、自動投稿設定変更の前に、必ず次をそのまま提示する。

- 投稿日時
- platform
- 投稿種別
- 画像パス
- 画像枚数
- 投稿本文
- ハッシュタグ
- 既知の制限、未確認点、リスク

ユーザーが明確に承認するまで投稿しない。曖昧な返事を承認扱いしない。

## 絶対停止条件

次のどれかに当たる場合は、作業を止めて質問する。推測、分割、代替画像生成、文面変更で回避しない。

- 投稿文が未確定。
- 画像が未確定。
- 画像枚数がplatform上限にぶつかる。
- ThreadsとInstagramで同一内容か別文か不明。
- 同じ時間に複数投稿が衝突する。
- 毎月1日の月次カルーセル投稿と、毎月1日以外の20:00投稿が同じ日に入りそうな場合。
- 毎日20:00枠の素材がない。
- 木曜20:00の比較系3種について、使用画像、順番、Instagram側の枚数が未確定。
- ユーザーが「今日だけ」「明日だけ」「来月から」などの期間指定をしている。
- ユーザーが「同じ画像を投稿するつもりはない」と言っている。
- 既存画像があるのに新規生成しようとしている。
- 外部投稿済みの削除、再投稿、上書きが必要になりそうな場合。

## 禁止

- 勝手に投稿文を作らない。
- 勝手に投稿文を言い換えない。
- 勝手にハッシュタグを抜かない。
- 勝手に画像を新規生成しない。
- 勝手に別日へ移動しない。
- 勝手に分割投稿しない。
- 勝手に同じ画像を繰り返し投稿しない。
- 古いJSONの本文を正本扱いしない。
- local dry-runだけで自動投稿完了と言わない。
- 投稿URL未確認のまま投稿成功と言わない。

## 誕生日系の必須条件

誕生日系Instagram投稿には、必ず次を入れる。

```text
#誕生日占い
#数秘
```

Threadsは同じ趣旨で出すが、ハッシュタグはplatformルールに従う。Instagram用の複数ハッシュタグをそのままThreadsへ流さない。

## 自動投稿の完了条件

「自動投稿できる」と報告できるのは、次を確認した後だけ。

- PCやCodexが起動していなくても動くクラウド実行経路がある。
- Render CronまたはGitHub Actionsの実行時刻がJST投稿時刻に合っている。
- Threads / Instagramの認証情報がクラウド側に設定されている。
- dry-runで対象投稿が正しい時刻にdueになる。
- 実投稿、または実投稿相当の検証で本文、画像、URL、重複有無を確認できる。
- 失敗時に検知できるログ、通知、または監査手順がある。

どれか未確認なら、未確認と明記する。120点と断言しない。

## 今すぐ確認が必要な未確定点

次の点は、実装や自動投稿設定の前にユーザー確認が必要。

1. 2026-07-01以降の月次 `21〜31日生まれ` は11枚で、通常のカルーセル10枚上限に衝突する。2026-06-06のリカバリ例外を他月へ勝手に流用しない。
2. 毎月1日以外の毎日20:00枠は、素材と文面がない日を投稿停止にするか、素材切れ通知だけにするか確認が必要。
3. 毎週木曜20:00の比較系3種は、Threadsでは3枚画像投稿。Instagram側の枚数、順番、使用画像が未確定なら質問する。

## 作業者への罰則相当ルール

このファイルの違反は、単なる軽微なミスではなく、外部投稿事故として扱う。

違反した場合は、次を必ず行う。

- 外部操作を即停止する。
- 何を、なぜ、どの指示に反して実行したかを明記する。
- ユーザーに追加作業をさせる前に、ローカル実装、docs、監査、テストのどこを直すか提示する。
- 同じ違反を防ぐテストまたは監査を追加する。
- 未確認の状態を完了扱いしない。
